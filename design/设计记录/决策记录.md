# 决策记录

Spine 设计过程中已经定下的事。**新会话开始先读这一篇**；和这里冲突的旧画板、旧导图内容，以这里为准。

来源：2026-10-13 ~ 10-14 在 Claude（claude.ai）里的设计对话、设计画布评论区、思维导图 v1–v3。

## 产品定位

- 面向**保守治疗（非手术）期**的脊柱侧弯患者。
- 两类用户：青少年（支具 + 高强度运动）和成年人（自主管理、改善体态与疼痛）。成年人市场有必要做：侧弯需要的运动和普通腰背训练很不一样。
- 成年人的心理机制和青少年不同，激励方式要分开考虑。
- **首发形态：先以轻量化的微信小程序上线**（2026-10-14）。目前设计的是完整 App 样板；小程序首版先把原型 v3 的全部页面搬过去，上线前再按需要删减。设计 demo 在团队仓库的 `demo/miniprogram/`；团队正式开发的小程序在 `miniprogram/`，两者是分开的。

## 首次使用与身份

| 决定 | 原因 |
|---|---|
| 不区分青少年 / 家长 / 成年患者身份，只问年龄和性别 | 青少年的手机常被家长管控、使用时间少，要尽量少让他们费心；两套视角会造成分歧 |
| 性别可选「自定义」，自定义的说法可以留空 | — |
| 没有家长视图、没有家庭共享 | 同上；家长需求另想办法（见「还没定」） |
| 信息逐步收集：首次只问年龄性别 → 选阶段 → 再填 2 项（初潮、手头资料） | 不繁琐，复查后再逐步补全档案 |
| 初潮一项只在性别选「女」或「自定义」时出现 | — |
| 五个阶段：还在检查 / 刚开始戴支具（前两周）/ 支具 + 运动 / 脱支具维持 / 成年自我管理；可在「我的」随时切换 | 治疗周期不同，首页内容不同 |

## 训练与打卡

| 决定 | 原因 |
|---|---|
| 打卡的核心形式：**卡片组计划 + 跟练式语音播报** | 用户原话：「1：卡片做组计划 2：keep 跟练形式」 |
| 施罗斯动作**不做通用视频库** | 施罗斯按弯型个性化，别人的矫正动作对你可能是反向的 |
| 动作示范来自患者复诊时自己录的视频 | 同上；康复师现场教的就是最适合本人的版本 |
| 动作命名分三层：显示名（康复师叫法）/ 标准动作 / 别名 | 康复师常用中文名或自创名，既要尊重原叫法，又要能对应到标准动作 |
| 今天的卡组是**一列**，不分两段 | 用户评论：「没有必要把它分成两段」 |
| 卡组顺序：柔韧 → 3D 矫正 → 核心 → 颈椎 → 拉伸放松（**待医生确认**） | 一组训练从柔韧到肌肉再到拉伸 |
| **隔天规则只在后台运行，页面不显示规则文字** | 用户评论：「隐藏起来写在 memory 里，不需要占用页面」 |
| 隔天规则：今天做了的隔天动作，明天不出现、后天回来；今天没做，明天继续出现。按实际练习日滚动，不固定星期几；目前按单个动作计算 | 用户评论原话见 [[评论区讨论]] |
| 保留训练页「本周安排」周视图的形式 | 用户：「这个模块的设计我觉得非常好」 |
| 跟练节奏随动作类型自动切换：计时 / 计数 / 呼吸 | 处方识别出组结构后驱动播报 |
| **不做镜子模式** | 「患者使用镜子模式跟踪不太现实并且很麻烦」 |
| 跟练时手机平放在地上，听声音练 | 替代镜子模式 |
| 完成页不放难度 / 疼痛评价卡 | 用户在画布里删掉了 |
| **先录后配**：复诊现场先录动作存草稿，拿到处方单后再拍照导入、把录像匹配到处方动作 | 很多患者先在现场学、之后才收到处方；先导入处方再逐个录制不符合实际（导图 v3 红色问题点） |
| 处方识别要识别出组结构（组数、次数、时长），并允许手动灵活修改 | 导图 v3 问题点 |
| 认知学习不放进每天的卡组，放到「社群 › 学习」，用松果轻度奖励 | 「不适合每天规划在任务当中」 |

## 支具

| 决定 | 原因 |
|---|---|
| 佩戴时长希望通过传感器自动记录 | 导图：联合生态，穿戴支具自动记录 |
| 支具衍生内容（饮食、皮肤、学校心理、游泳放松、经期）不进主功能，作为「支具生活」放进社群 | 用户评论：「融入社区功能当中」 |
| 「我的支具」页只保留佩戴记录 | 同上 |

## 复查与成长记录

| 决定 | 原因 |
|---|---|
| 复查提醒是**可选功能，默认关闭**；打开后复查日期也可以不填 | 生硬的倒计时会加剧焦虑 |
| 首页不显示复查倒计时；提醒打开时，只在复查前出现「准备清单」卡片 | 同上 |
| 「我的」里有复查提醒方式三选一：复查前一周再提醒 / 一直显示倒计时 / 不在 App 里提醒 | 让喜欢心里有数的人也能选 |
| 成长记录顶部只保留：治疗历程（第 N 天，自确诊起）、戴支具天数、训练次数 | 用户评论：「其余的功能都删除」 |
| 治疗历程**不配**里程碑勋章 | 试过「历程勋章」进度线，被否决 |
| 复查记录拍照识别打印的报告；**不做手写识别** | 用户评论 |
| 识别出的字段可手动改：右上角「⋯」进入编辑 | 用户评论；识别有误差 |
| Cobb 角有 ±5° 测量误差，差 5° 以内不用紧张，界面上要说明 | 减少焦虑 |

## 激励

| 决定 | 原因 |
|---|---|
| 松果是货币，用来**补打卡**（不兑换实物） | 导图 v2 |
| 支具和训练分开计奖：训练完成 +3、支具达标 +2、认知学习小测 +2、复查后上传 +5；补卡消耗 10 | 一项没做到不影响另一项 |
| 「今天的松果」里未达成的项目显示「待完成」 | 用户评论 |
| 勋章 6 枚：熬过第一周、学会 5 个动作、第一次复查记录、坚持 4 周、支具达标 30 天、训练满 30 次。只看坚持，不看度数 | 阶段性成就感，但避免焦虑 |

## 社群

- 板块：小组、搭档打卡、支具生活、Deco 装饰、学习。
- 科普只出现在「社群 › 学习」一处，不和其他页面重复。

## 隐私与呈现

- demo 里不用真实照片、不用真实姓名（示例人物「小禾」）；真实患者资料不进仓库。
- 不知道的数据不编造。
- 视频只保存在本机。
