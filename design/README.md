# Spine · 设计资料

思维导图、功能对照和设计决策。这个文件夹同时是一个 **Obsidian 库**：在 Obsidian 里「打开本地库」时选 `design` 文件夹，就能直接查看和编辑思维导图（`.canvas`）和笔记。用 Claude Code 时也在这个文件夹里启动，它会先读 `CLAUDE.md`。

可点击体验的 demo 在 [`../demo`](../demo)。

| 位置 | 内容 |
|---|---|
| `设计记录/决策记录.md` | **最重要**：所有已定的规则和原因，以及还没定的问题 |
| `设计记录/领域知识.md` | 医学背景、示例处方结构、视觉规范（颜色、字体、尺寸） |
| `设计记录/对话纪要.md` | 设计过程，按时间顺序 |
| `设计记录/评论区讨论.md` | 设计画布上 12 条评论的原文 |
| `思维导图/思维导图 v1、v2、v3.canvas` | 三版原始导图，只读：v1 初版构想 → v2 标出问题点 → v3 新问题与构想 |
| `思维导图/功能对照.canvas` | v3 导图原样保留，下方连到功能笔记，颜色表示实现状态 |
| `功能/` | 18 篇功能笔记；`功能总览.md` 是状态总表 |

功能对照的颜色：绿 = 已实现，黄 = 部分实现，红 = 待医生确认，紫 = 已决定（包括决定不做的）。

## 和团队 PRD 的差异（待讨论）

这些设计和 demo 是在另一组对话里做的，和仓库根目录的 `SPINE_PRD_v1.md`（2026-10-11）有不一致的地方。两边谁为准，需要团队讨论后定，这里只列出差异。

| 方面 | 本设计 / demo | 团队 PRD v1 |
|---|---|---|
| 底部导航 | 5 个：今日 / 训练 / 成长 / 社群 / 我的 | 4 个：今日 / 社区 / 专业服务 / 个人；写明「此前三入口与五入口方案已被替代」 |
| 专业服务 | 只在「我的 › 康复团队」里占位，标「即将开放」 | 独立入口：康复师对话、已关联人员、找附近医院和支具机构 |
| 首次使用 | 问年龄、性别、所处治疗阶段（5 个阶段） | FR-01：康复管理 / 运动养护多选，加支具开关 |
| 支具佩戴时长 | demo 演示传感器自动记录 | 支具硬件连接未定，不作为默认承诺；FR-12 为穿脱记录 |
| 佩戴目标 | 示例目标写成 20 小时（刚戴支具时 8 小时） | FR-11：目标不能默认为某个小时数；没有目标时不计算达标 |
| 动作来源 | 「先录后配」：现场录像，处方拍照后自动推荐配对 | FR-08：上传资料标记「本人录入 / 待核对」，正式内容优先匹配已审核动作库；依赖矫正方向的内容不默认开放自主执行 |
| 运动养护 | 没有单独模块；成年人阶段只有维持训练 | FR-10：独立的运动养护课程体系，和康复计划分开统计 |
| 激励 | 松果可以补卡；6 枚坚持勋章 | FR-20：累计记录不因断签清零，不奖励超目标佩戴；补卡机制需要和这一条对齐 |

两边一致的地方：
- 不做家属分账号；
- 不用照片或训练量推算 Cobb 角；
- 复诊前整理摘要；
- 不做排名。
