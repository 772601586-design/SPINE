# CLAUDE.md（design 文件夹）

这里是「Spine」的设计资料，同时是一个 Obsidian 库。仓库由团队共建，交流用中文。

本文件只管 `design/` 和 `demo/` 两个文件夹。团队的正式代码（`miniprogram/`、`backend/`、`frontend/`、`flutterapp/`）以根目录的 `SPINE_PRD_v1.md` 和 `ai_path/` 为准，**不要修改它们**。

## 新会话先读

1. `设计记录/决策记录.md`：已定的规则和还没定的问题。**和旧画板、旧导图冲突时以它为准。**
2. `设计记录/领域知识.md`：医学背景、示例处方结构、视觉规范。
3. 改小程序 demo 前读 `../demo/miniprogram/README.md`（代码结构、导航规则）。
4. `README.md` 末尾列了本设计和团队 PRD 的差异，改动前先看是否涉及。
5. 需要来龙去脉时再看 `设计记录/对话纪要.md` 和 `设计记录/评论区讨论.md`。

做出新决定时，补进 `决策记录.md` 对应的表格，并从「还没定」里勾掉。

## 目录

- `../demo/miniprogram/`：小程序设计 demo（示例数据，不接后端）。
  - 业务逻辑在 `core/spine-app.js`，和网页原型是同一份。
  - 排卡规则在 `core/scheduler.js`。
  - 状态和导航在 `core/store.js`。
  - 改完运行 `node tools/check.js .`，应输出 `PROBLEMS 0`。
  - `tools/build.py` 会从画布原型重新生成 `pages/` 和 `core/spine-app.js`，**会覆盖手动修改**，谨慎使用。
- `design/`（本文件夹）：设计资料，也是 Obsidian 库的根目录。
  - `思维导图/思维导图 v1|v2|v3.canvas` 是历史版本，**只读**。新思路写进新版本文件或功能笔记。
  - `功能/<功能名>.md`：每个功能一篇。frontmatter 里有 `status`（已实现 / 部分实现 / 待确认 / 已决定）、`demo`（在原型里的位置）、`mindmap`（对应的 v3 导图节点 id）。正文四节：对应思维导图 / 现在的做法 / 已定的规则 / 还没定。
  - `思维导图/功能对照.canvas`：v3 导图副本加上一排功能卡片。卡片和连线的颜色就是状态：绿 4、黄 3、红 1、紫 6。功能状态变化时，同步更新笔记、这张画布和 `功能/功能总览.md`。
- `../demo/web/spine-prototype.html`：单文件网页原型；`../demo/canvas/`：设计画布导出的源文件，不能直接用浏览器打开。

## .canvas 格式（JSON Canvas）

- 顶层是 `{"nodes": [...], "edges": [...]}`。节点 `type` 为 text / file / group / link；`color` 为 `"1"`–`"6"`，依次是红、橙、黄、绿、青、紫。
- 原导图里橙色（"2"）文字框是用户标出的「问题点」，红色（"1"）是特别重要的问题。
- 编辑后保持 JSON 合法、id 唯一，新节点不要压住已有节点。

## 隐私规则

- 永远不要提交真实患者的姓名、病历、处方或诊断原件（PDF、照片）。
- 示例人物用「小禾」，医院用「某康复中心」。
