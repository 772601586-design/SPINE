- **落盘后按魔数复核**类型（jpeg/png/webp/pdf/mp4），不符则删除文件并报 `UNSUPPORTED_FILE_TYPE`——只信扩展名与客户端自报 MIME 是不够的。
- DICOM（`.dcm`）给**专门提示**而非笼统拒绝（§4.1）。
- 幂等表**不保存响应体**，只存 `object_id` + 状态码，重放时按 id 重新序列化，避免把疼痛分/病历摘录复制到第二张表。
- `Profile.diagnosis_status` 可空（建档只强制昵称）；`birth_month` 存 `YYYY-MM` 字符串（不拿某月 1 日冒充「只知道年月」）；`management_methods` 用受控 code 列表并去重保序。
- **身高体重不写回档案**：`GET /me/profile` 返回派生的 `latest_measurement`，历史行不被覆盖。
- 新增 `GET/PATCH /api/v1/me/`（身份 + `has_profile`）与 `GET/PATCH /api/v1/me/profile/`；`PATCH /me` **等价于** `PATCH /me/profile`（用户可写资料只有档案字段，不造第二个语义不明的写入口）。旧的 `/auth/me/` 保留。
- `AvatarField.to_representation` 必须返回完整对象（要生成签名地址），因此重写 `use_pk_only_optimization()` 返回 False——否则 DRF 传进来的是 `PKOnlyObject`，读 `.status` 直接 AttributeError。

**关键设计决策**
- **日期精度三态互斥**由库层 `CheckConstraint(visit_date_precision_exclusive)` 兜底：`day` 必须有 `visit_date` 且 `visit_month` 为空，`month` 反之，`unknown` 两者皆空。序列化器可省略 `date_precision` 由字段内容推导，但一旦传入必须自洽（矛盾组合 400）。**坚决不用 1 月 1 日冒充未知日期。**
- **`Visit.Meta.ordering` 用 `F("visit_date").desc(nulls_last=True)`**：PostgreSQL 在 DESC 下默认 NULLS FIRST，不显式声明会让「日期不详」的就诊排到时间线最前，冒充"最近一次就诊"。
- `MedicalAttachment`：`attachment` 是 `OneToOneField` + `UniqueConstraint(attachment)` → **一张附件只能属于一次就诊**；绑定时校验 `purpose == medical`（社区媒体不能混进医疗档案，§4.3）、`owner` 本人、`status == ready`；并发绑定用 `select_for_update` 锁就诊行，`VISIT_MAX_ATTACHMENTS`（默认 20）不可被并发绕过。
- **解绑 ≠ 删原件**：`DELETE /visits/{id}/attachments/{aid}` 只删绑定行，附件仍是本人私有对象（medical 用途不对他人开放），由 Task #16 的孤儿清理兜底。
- `CurveMeasurement`：全部字段可空/未知（`region` 有 `unknown` 选项），允许只知道"有几个弯"不知道角度；`source_attachment` 必须是**同一次就诊**的附件；`entry_source` 固定 `manual`（保留字段为将来区分 OCR 来源，现在不声称有 OCR）。
- **DRF `@action` 同一路径只能注册一个**：PATCH/DELETE（改分类/解绑）必须合并进一个方法，GET/POST（列/增弯曲）同理——同一 `url_path` 挂两个 `@action` 时只有第一个会被匹配，第二个直接 405。
- `retrieve`/`PATCH` 返回 `VisitDetailSerializer`（嵌套附件含短期地址 + 多弯），列表用轻量 `VisitSerializer`（含 `attachment_count`/`curve_count`），避免列表里为每条就诊签一堆令牌。
- 删除就诊 = 真删：`MedicalAttachment`/`CurveMeasurement` 级联删除；计划侧的快照与「原记录已删除」在阶段二随 `Plan.reference_visit_id` 落地。
