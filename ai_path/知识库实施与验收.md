## 3. 数据模型与版本规则

新增表使用 Django `knowledge_*` 前缀：

| 模型 | 用途 |
|---|---|
| Category、Question、Tag、Topic | 六个问题分类、患者问题、医学关键词／同义词、专题目录 |
| Article | 稳定 ID、发布状态、已发布版本指针、撤稿原因 |
| ArticleVersion | 标题、摘要、正文、适用人群、关键词、风险、内容类型、分类／问题／标签／专题多对多关系、编辑人、修订号和复核日期 |
| Source | 文献标题、机构／期刊、作者、年份、URL、DOI、PMID、证据类型、适用范围及四级核验状态 |
| Claim、ClaimSource | 版本中的重要结论、正文位置、原文章节／页码／表格、适用限制、核验人和原文快照 |
| Review | 审核意见、实际审核账号、时间、内容摘要校验值 |
| Bookmark、Feedback | 当前用户收藏、版本级纠错及处理结果 |
| CommunityLink | 文章和原有已发布社群帖子的显式关联 |
| ImportJob、AuditLog | 导入内容与清单、预览、错误、提交／回滚，以及只读操作历史 |

文章基础信息在版本表内，而不在 Article 上重复保存；读取对外信息时必须经过 `published_version`。这避免未发布版本的标题、分类或正文被新编辑覆盖。

流程：`draft → submitted → changes/approved → publish`；审核后的版本不能原地修改。创建下一版本会重新生成待核验的结论关系。编辑人不能审核自己的稿件；超级用户也不自动具有医学审核角色。审核通过要求独立审核账号逐条确认重要结论、核查所有文献，并确认素材使用权。发布还会再次校验审核摘要和来源状态。

发布时保存完整文献快照。以后编辑 Source 会重置该来源的核验状态并提示关联文章复核，但已发布版本的参考文献快照保持不变；明确失效／撤回的来源会阻断其关联文章公开访问。网络检查失败不自动判定文献撤回。

复核期当前默认为审核后 180 天，是内容运营提醒，不是患者复诊计划。

## 6. 导入、编辑与医学审核操作

后台“导入”选择文件后先看预览、错误与警告，再点击“确认导入为草稿”。任何一条格式错误或重复 ID 都阻止整个批次写入。重复提交同一个导入任务不会重复创建记录。新增文章的导入与覆盖已有文章分开：已有 ID 必须走版本流程。

CLI 同样复用这一流程：

```powershell
.\.venv\Scripts\python.exe manage.py import_knowledge 'D:\完整文件路径.zip' --user 已有编辑账号 --report preview.json
.\.venv\Scripts\python.exe manage.py import_knowledge 'D:\完整文件路径.zip' --user 已有编辑账号 --commit --report import-report.json
.\.venv\Scripts\python.exe manage.py import_knowledge --user 已有管理员账号 --rollback 导入任务UUID
```

回滚仅删除该批次尚未编辑、未审核、未发布且未关联的草稿。存在后续工作时整个回滚失败，保护编辑成果；已修改或被其他文章引用的来源不会被删除。

JSON 可用文章数组或 `{ "articles": [...] }`；CSV 第一行为字段名，数组单元格优先使用 JSON 字符串，也可用分号分隔文本；Markdown 使用 YAML front matter。格式示例见 `backend/knowledge/examples/article.md`，它不是医学内容。所有格式均保留外部审核声明，但不将其转为平台医学审核通过。

编辑文章时补全独立章节、适用人群、关键词及风险等级，关联文献并逐条填写“重要医学结论—正文位置—原文定位”。支持 Markdown 标题、列表、引用、图片及替代文字、独立图注段落、表格；原始 HTML 被禁用，并经过允许列表清洗。正文不能嵌入私人附件 URL、签名令牌、本地文件或内联 data URL。

独立医学审核人员先核对来源，再逐条核对结论的支持程度、具体位置和适用限制；后台保留其实名显示名称／实际账号、意见及时间。需要修改时退回；通过后由管理员发布。不要删除原稿的待审核声明直到实际完成该版本内容整理与审核。

## 7. API 与数据隔离

所有路径位于 `/api/v1/knowledge/`，继续使用现有 Token 认证。公开读取不强制登录，个性化收藏结果仅限当前用户。

| 路径 | 方法 | 用途 |
|---|---|---|
| `catalog/` | GET | 六分类、六专题、已发布推荐、常见问题 |
| `articles/` | GET | `q/category/topic/question/bookmarked/page/page_size` 综合检索与分页 |
| `articles/{id}/` | GET | 文章、医学结论、来源快照、审核记录及相关内容；撤稿返回 410，未公开返回 404 |
| `sources/{id}/` | GET | 仅公开文章引用的文献 |
| `articles/{id}/bookmark/` | PUT／DELETE | 幂等收藏／取消，按当前用户隔离 |
| `articles/{id}/feedback/` | POST | 当前文章版本的错误反馈 |
| `manage/dashboard/`、`manage/articles/` | GET／文章 POST | 角色、统计、版本列表与新建 |
| `manage/versions/{id}/` | GET／PUT | 版本读取与基于 revision 的冲突保护编辑 |
| `manage/articles/{id}/versions/` | POST | 克隆为下一草稿版本 |
| `manage/versions/{id}/{submit,changes,approve,publish,withdraw}/` | POST | 受角色和状态双重限制的流程操作 |
| `manage/{categories,topics,tags,sources}/` | GET／POST；明细 PATCH | 分类、专题、专业标签、文献管理 |
| `manage/sources/{id}/verify/`、`manage/evidence/{id}/verify/` | POST | 独立文献与结论核验 |
| `manage/imports/`、`manage/imports/{id}/{commit,rollback}/` | multipart POST／POST | 文件预览与批次处理 |
| `manage/feedback/`、`manage/community-links/`、`manage/audit/` | GET；受控处理 POST | 纠错、社群关联、只读审计 |

分页响应是 `{ "data": [...], "meta": { "count": 68, "page": 1, "next": 2, ... } }`。两端知识库适配器会重建 `results`，旧模块不受影响。搜索使用数据库查询和加权排序，标题和患者问题优先，支持 Cobb／侧弯度数、施罗斯／Schroth、矫形器／支具及可维护同义词。

推荐、搜索、问题、详情、关联文章、收藏和公开文献均复用发布过滤条件。所有知识库 API 设置 `Cache-Control: no-store`，避免撤稿和用户收藏被共享缓存继续展示。
