# 训练页面设计落地

日期：2026-10-17。修改对象为根项目当前运行的 `miniprogram-demo/`，保留 `spine1/demo/miniprogram` 原始参考目录。

## 设计对应

- 采用较新的 `output/design/xiaoshu-merged-training.png`：今日与训练合并，按日历 → 当日清单 → 草稿 → 动作卡 → 计划顺序布局。保留现场录制快捷入口，底部为训练、成长、社群、我的四项。
- 沿用 `xiaoshu-training-flow.png` 的六步逻辑：现场录制 → 整理动作卡 → 建立计划 → 当日执行 → 保存实际量 → 成长回顾。
- 录制结束将视频复制到小程序本机文件目录并保存草稿，可连续录多段；可从相册补充。补充处方单保存真实图片原件并返回动作卡，不再展示固定的“识别出 12 个动作”作为本流程结果。
- 动作卡统一支持学、练、查。个人要求含计时 / 计数 / 呼吸、组数、每组完成量与个人要点；可先存草稿。只有本人核对并保存后才能加入计划；修改要求后需要重新核对。
- 计划可选每天、固定星期、按完整完成日隔天、周期内若干次；可选择并调整动作顺序，设置开始日及暂停 / 恢复。
- 当天清单依据日程生成，圆圈表示本次全部要求已完成，点击进入实际量核对。计划暂停和未来日期不产生新的实际执行记录。
- 跟练按实际时间计时 / 计数，支持暂停、切组、数字语音与手动确认。跟练和手动操作修改同一训练会话、同一动作、同一组，重复保存不会重复累加。
- 实际量可按组记录、添加额外实际组、填写感受。空白与明确填写 0 分开保存；额外组不会修改原要求。计时结束或播放结束不自动确认完成。
- 补记使用真实日期、免费，不扣松果。旧今日入口和欢迎引导均转到合并训练页，原奖励页补记入口也已改为免费实际记录。
- 成长页展示本周已记录次数、部分完成次数、周视图、全部训练历史和可复制汇总。历史保留开始记录时的计划名称、动作要求及各组实际值，后续计划或卡片编辑不覆盖它们。

## 数据与边界

本轮属于本机 demo 页面与逻辑实现，使用 `xiaoshu.training.flow.v2` 独立存储，未将正式接口版的模型作为演示数据源。新初始化有两张标明示例来源的动作卡和一个每日示例计划，不预置完成记录。视频、处方单图片、练习对照视频均保存在本机；清理小程序数据会移除本机资料。

新补记若没有原先的训练会话，使用所选计划当前已核对要求建立快照，再由本人核对真实完成量；已存在的历史会话继续使用原快照。暂未实现跨设备同步。当前浏览器 demo 已接入病例单与训练方案单的本机文字识别和核对补充，见[现场记录与单据整理](./现场记录与单据整理.md)。

## 验证

`node scripts/check-demo.cjs` 验证当前设计基线、四标签、所有页面注册文件与 JavaScript 语法，并运行专项场景：草稿核对门槛、固定星期 / 隔天 / 周期安排、部分完成、跟练与手动共享进度、重复保存、免费补记、历史快照、额外组、存储失败不篡改原数据、欢迎引导及旧奖励入口跳转。

微信开发者工具自带 WXML / WXSS 编译器检查当前页面。尚未进行真机录制、音频播放及视觉验收。

原来的 `sync-demo.cjs` 在检测到新设计标记时会拒绝覆盖，避免误将当前逻辑还原为旧 demo。
