## 1. 安装项目依赖

打开普通 PowerShell：

```powershell
cd D:\SPINE
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup.ps1
```

脚本只安装项目依赖，不安装系统工具；已有 `.env` 不覆盖。
完成后生成 Python 传递依赖 `backend/requirements.lock` 和 npm `frontend/package-lock.json`。
Flutter 使用已提交的 `pubspec.lock` 并要求严格遵守锁文件。
将首次正常解析生成的两个新锁文件保留在版本库中；之后 Python 用 `pip install -r requirements.lock`，React 用 `npm ci`。

如果希望分开执行，便于排查：

```powershell
cd D:\SPINE\backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.in
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pip freeze | Set-Content -Encoding UTF8 requirements.lock
.\.venv\Scripts\python.exe bootstrap_env.py

cd D:\SPINE\frontend
# 若已有 package-lock.json，使用 npm ci；首次生成锁文件使用 npm install。
npm install
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm run build

cd D:\SPINE\flutterapp
flutter pub get --enforce-lockfile
flutter analyze
```

项目已经有本轮创建的 `.venv`。如该环境无法使用 pip，先运行 `.venv\Scripts\python.exe -m ensurepip --upgrade`，不要安装到系统 Python。

## 3. PostgreSQL

可以选择安装 PostgreSQL 17，或安装 Docker Desktop 并启用 WSL2。
本轮没有替你安装这些系统工具。

选择 Docker 后，在根目录执行：

```powershell
cd D:\SPINE
python backend\bootstrap_env.py
docker compose --env-file backend/.env up -d postgres
docker compose --env-file backend/.env ps
```

Compose 从本机 `.env` 读取数据库密码，固定 PostgreSQL 镜像版本，数据保存在命名卷。
无需自行把密码填入代码。已有数据库卷修改环境密码不会自动修改数据库里的密码，需保持配置一致。

选择本机 PostgreSQL 时，在 pgAdmin 中创建 `spine` 登录角色和同名数据库，由该角色拥有；密码自行设置到 `backend/.env`，其余地址与端口按实际安装填写。

数据库启动后停止预览后端（Ctrl+C），在后端终端执行：

```powershell
cd D:\SPINE\backend
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000 --noreload
```

再次访问 `/api/v1/ready/`，应得到 200 和 `database=ok`。
`migrate` 目前只创建 Django 基础表，没有业务模型。

## 4. Android 模拟器 / 真机

在开发终端中设置已发现的 SDK/JDK 路径，仅影响本次终端会话：

```powershell
$env:ANDROID_HOME='D:\app\androidstudio\sdk'
$env:JAVA_HOME='D:\app\androidstudio\android studio\jbr'
$env:PATH="$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:PATH"
flutter doctor -v
```

需要时按照 doctor 的提示检查 Android SDK licenses。Android Studio 中启动模拟器，运行 `flutter devices` 获取设备 ID。

后端绑定 `0.0.0.0:8000`，Android 模拟器通过 `10.0.2.2` 访问电脑：

```powershell
cd D:\SPINE\backend
.\.venv\Scripts\python.exe manage.py run_api 0.0.0.0:8000 --skip-migration-check --noreload

# 另一个终端
cd D:\SPINE\flutterapp
flutter run -d <Android设备ID> --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

Android debug 构建允许本地 HTTP；release 构建使用 HTTPS。
真机需与电脑在同一局域网，API 地址换成电脑局域网 IP，并将该 IP 加入 `DJANGO_ALLOWED_HOSTS`；Windows 防火墙需允许局域网访问该开发端口。后端只运行无业务数据的开发预览。
iOS 平台文件已建立，实际构建需 Mac；debug 配置允许本地 HTTP，release 不开放任意 HTTP。
