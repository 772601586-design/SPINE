# SPINE 微信小程序 · 启动与验收

更新日期：2026-10-12。个人端迁移目标已经从 Flutter 改为原生微信小程序；本轮冲突以本说明为准。`flutterapp` 保留作迁移参考并暂停新增功能，`frontend` 仍是专业工作台与审核后台，Django/PostgreSQL 继续提供共享业务接口。

## 工程与导入

- 小程序源代码目录：`D:\SPINE\miniprogram`。
- 原生文件：TypeScript、WXML、WXSS、`app.json`；不使用 WebView 包装。
- 在微信开发者工具选择“导入项目”，目录填写 `D:\SPINE\miniprogram`。项目配置在 `project.config.json`，个人端 AppID 填写位置是该文件的 `appid` 字段，目前留空，没有编造 AppID。
- 工具安装目录中未发现微信开发者工具，因而本轮没有在模拟器、真机或当前工具版本中编译/点击验收。若工具不允许空 AppID，请在“导入项目”界面使用你自己的小程序 AppID；若没有 AppID，只能在当前工具提供的本地测试/游客模式中尝试，具体入口名称因未能启动工具而未核实。
- `tsconfig.json` 为严格 TypeScript 检查配置；`project.config.json` 启用 TS 编译。`typings/wechat-mini.d.ts` 是当前代码所需 API 的本地最小类型声明，并非微信完整官方类型包。官方维护的完整类型定义可用 [wechat-miniprogram/api-typings](https://github.com/wechat-miniprogram/api-typings)，可在正常联网环境安装 `miniprogram-api-typings` 后替换本地最小声明。
- 未固定基础库版本（`libVersion`）；导入时使用开发者工具提供的当前稳定版本，并用真机预览复核。代码使用 `wx.request`、本地存储、页面/导航等小程序核心 API。本轮无法从微信官方开放文档核实具体最低基础库版本，不能将某个猜测版本写成要求。

## 后端启动

本机 PostgreSQL 数据目录是项目已有的 `.tools/postgresql-data`，保留其数据，不运行 `initdb`、不删除数据库、不删除迁移。启动前先检查端口，避免重复起服务：

```powershell
cd D:\SPINE\backend
.\.venv\Scripts\python.exe local_postgres.py status
```

若它明确报告数据库未就绪，且配置仍指向本项目本机数据库，再运行：

```powershell
.\.venv\Scripts\python.exe local_postgres.py start
.\.venv\Scripts\python.exe manage.py migrate --noinput
.\.venv\Scripts\python.exe manage.py create_dev_accounts
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py run_api 127.0.0.1:8000 --noreload
```

当前已在 `127.0.0.1:8000` 启动本轮最新代码；健康与真实数据库就绪接口均返回 200。若端口被其他程序占用，先确认进程归属再处理，不要强行启动第二个服务。小程序本机开发地址在 `miniprogram/config/environment.ts` 的 `developerTool` 配置。

开发账号为 `spine_a` 和 `spine_b`，本机密码从 `backend/.env` 的 `SPINE_DEV_PASSWORD` 读取；文档、命令行输出和小程序包不保存明文密码。没有现成密码时不要重置已有账号；由项目所有者本地查看该环境配置。

## 开发者工具、电脑、手机和正式环境

- **开发者工具本地联调**：`API_BASE_URL` 当前是 `http://127.0.0.1:8000`。项目配置含 `urlCheck: false`，只为本地开发联调；若当前开发者工具仍拦截本机地址，可在工具“本地设置”中为本地开发临时关闭请求域名校验。该选项不构成正式发布配置。
- **手机真机**：手机上的 `127.0.0.1` 指手机本身，不是电脑。把 `RUNTIME_TARGET` 切到 `device`，将 `API_BASES.device` 填为电脑在同一 Wi-Fi 下可达的局域网地址；Django 绑定 `0.0.0.0:8000`，并把该 IP 加入本机 `backend/.env` 的 `DJANGO_ALLOWED_HOSTS`。还需允许防火墙接收开发端口。微信真机调试的 HTTP/TLS 限制与工具选项须以当前官方工具和账号实际提示为准；本轮未使用真机验证。
- **体验版/正式环境**：把 `RUNTIME_TARGET` 切为 `release`，配置真实 HTTPS API 域名，将该域名按微信后台要求加入 request 合法域名，并恢复域名校验。当前没有提供生产 API 域名、证书、备案/合法域名配置或 AppID；`release` 地址有意留空，避免伪造线上配置。
- 小程序网络请求不依赖浏览器 CORS。没有为了小程序放宽 Django CORS 或后端认证；业务接口仍要求 DRF Token，并按本人过滤数据。

## 当前闭环

- 启动先验证本地令牌与 `/api/v1/auth/me/`。令牌无效（401）清理存储并回登录页；普通网络失败保留会话，并提供重试。密码仅在登录请求中传送，不存储；令牌通过小程序本地存储保存，退出请求后清除本地存储和页面栈。
- 登录成功进入今日 Tab。四个入口是今日、社区、专业服务、个人。社区、专业服务、未接入的计划/运动/上传等明确显示未开放状态。
- 支具档案支持新增、编辑、类型、使用日期、配置机构、备注和停用。当前选中支具与任何未结束佩戴记录分开展示；有未结束记录时不能停用该档案，不能开始第二条计时。
- 佩戴开始、结束、补录、修正、历史、修改历史、按支具的日/周统计、感受新增/编辑/历史、痛感空值与 0 分、舒适度 1—5、位置/标签多选、后续缓解/仍存在/加重均连接真实 Django 接口。跨日拆分仍由后端按 `Asia/Shanghai` 计算。
- 没有真实佩戴目标时不显示目标/达标率。照片附件、专业共享、专业制定目标、回复/处理状态及提醒未实现，不显示假上传、假发送或假目标。
- 认证接入位置在 `services/session.ts`：现在使用账号密码联调。后续 `wx.login` 应只把 code 发给 Django，由服务端调用微信接口并关联现有用户、签发本项目 Token；AppSecret 与 session_key 不下发客户端。

## 最短手动验收

1. 导入 `D:\SPINE\miniprogram`，先选择本地测试模式或填写你自己的 AppID；在当前工具中编译并确认登录页。
2. 使用 `spine_a` 和本机开发密码登录，确认出现四个 Tab，默认位于“今日”。点“支具”卡片进入支具管理，使用标题栏返回。
3. 新增支具，填写名称与类型；点“已戴上”，切到其他 Tab 再返回支具页，应继续显示同一未结束记录及按服务端时间计算的暂计时长。
4. 点“已取下”，再打开“完整历史”和“趋势统计”。用无冲突日期补录上海时间 23:30 至次日 01:00，应分别统计 30、60 分钟；修正结束时间后，统计与修改历史应刷新。
5. 记录一条痛感留空的感受，再记录痛感 0 分；历史应分别显示“未填写”和“0 分”。在第一条追加“缓解”，确认后续历史能读取。
6. 退出后登录 `spine_b`，确认 A 的档案、佩戴与感受不可见；再退出。通过刷新/重新打开检查有效令牌恢复；服务端令牌失效后应回登录页。断网时页面应提示重试且不清除仍可能有效的会话。
7. 检查窄屏滚动和返回导航。当前未安装微信开发者工具，本步骤待工具可用后完成。
