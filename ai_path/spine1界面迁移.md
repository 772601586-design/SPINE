## 第三轮：真实日期卡组与训练完成页

- 动作卡新增 `schedule_frequency`，可填写每天、隔天或留空。旧卡片保持留空，不自动推断频率；修改需保存核对。该字段纳入动作修订历史与计划快照。`training.0003_personal_schedule_frequency` 已在本地 PostgreSQL 应用。
- 新增 `GET /api/v1/training/today/`，按服务端上海日期、计划日期范围、卡片核对状态和个人顺序排卡。返回今日完成进度、明日预览、休息与待设置数量，以及未结束训练入口。客户端日期参数不改变实际排卡日期。
- 每天动作每天出现；隔天动作完成当天保留并标记完成，次日休息，第二天恢复；从未完成或未练则继续顺延。完成日取已结束完整训练中最后一组的确认日期。部分完成计入当日实际组数，但不记为完整动作，也不触发隔天休息。跨日训练以最后一组日期归属完整完成；当日组数仍按每组各自确认日期统计。
- 明日预览基于已保存记录，不预测尚未完成的训练。无频率或未核对卡片在训练页整理，不进入今日卡组。治疗阶段不改变动作集合。今日页可见期间每 30 秒检查跨天，切页或回到前台会重新读取。
- 今日支持直接开始第一项和恢复未结束训练；新增训练完成页展示本次记录与今日进度，并可继续下一项。下一项开始前会重新读取卡组；部分完成后该动作仍可能是下一项，由用户决定是否继续。
- 修复跟练返回前台后的暂停状态同步，以及保存一组后刷新失败提前删除本地请求的问题。重试始终复用请求编号，成功读取服务端进度后才删除本地待同步记录。添加实际完成量校验和重复提交保护。
- 验证：`manage.py test training profiles --noinput --keepdb` **49 项通过**，包含新排卡边界与真实 API 打卡重试测试；Django 检查、迁移漂移检查、小程序 TypeScript 检查通过。OpenAPI 校验 0 错误，保留 1 个 category 枚举命名警告。页面模拟覆盖今日开始/恢复、跟练暂停、保存成功但刷新失败的重试、完成页与继续下一项；WXML 结构检查通过。尚未完成微信开发者工具或真机视觉验收。

## 第四轮：先录后配与本机示范

- 训练页新增现场录像入口及待整理数量；支持通过相机录制或从相册选择、命名、预览并保存为待整理。单段限制 50 MB，存储不足时保留未保存提示。通过文件系统将临时录像复制到用户数据目录，不依赖临时文件路径长期存在。
- 新增人工配对页，对照本人处方从已有个人动作卡中选择，保存前重新验证动作仍属于当前账号且处于有效状态。未匹配的录像继续保留，可以更换配对、取消配对或删除录像。每段录像最多关联一个动作，同一动作可有多段录像。
- 动作卡新增「我的现场示范」，显示配对的视频；缺失文件显示重新录制提示。录像配对只存在本机，不改变动作参数、计划或审核状态。
- 按 demo 关于录像只存本机的约定实现，不将私人录像上传到现有公开可读的动作素材用途。视频文件及目录按登录用户 ID 隔离，索引只引用当前账号的受控目录；录制保存期间切换账号会取消索引写入并清理新副本。
- 退出登录时清除令牌、待同步组记录及其他缓存，保留按账号隔离的本机录像索引。只有重新登录原账号才能在界面看到原录像。清理小程序数据或换设备无法恢复，请保留原片。无云端视频同步或自动处方匹配。
- 验证：`npm run typecheck`、`npm run check:wxml`、`npm run check:recordings` 通过；本机录像检查覆盖持久副本、配对/取消配对、隔离、保存失败回滚、大小限制、保存中账号变化、退出后保留、文件丢失、路径校验、页面流程、动作失效及删除确认。使用已安装开发者工具自带 `wcc.exe` 实际编译 **25 个 WXML 页面通过**。真机相机、文件配额及视频解码/播放仍未验收。
