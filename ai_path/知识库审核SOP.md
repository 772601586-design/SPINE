# 知识库医学审核 SOP（给审核人）

更新日期：2026-11-03。适用对象：持有 `knowledge_reviewer`（及发布所需的 `knowledge_admin`）角色的真实审核人员。

本文件只写“怎么操作 + 什么会被系统拦住”，不代替任何医学判断。审核结论必须由审核人本人依据原文作出。

## 1. 登录

打开工作台 → 输入账号密码 → 「登录工作台」。顶部显示「草稿 / 待审核 / 公开」计数。计数与实际不符时点「重新连接工作台」。

## 2. 先核验文献（`Source`）

`approve` 的前置条件之一是**本篇所有关联文献都是 `verified`**，所以先做这一步。

1. 切到「文献与分类」页签，左上选择「文献」。
2. 点一条文献（右侧按钮列表），下方出现「结构化元数据（JSON）」。
3. 逐个字段核对：标题、机构／期刊、作者、年份、URL、DOI/PMID、证据类型、适用范围。发现错误**先改元数据并「保存元数据」**，再核验——注意保存会重置核验状态。
4. 在「原文核验意见」写清楚依据，例如：`已打开原文 pdf 第 3 页 Table 2，确认样本与结论；链接可访问`。
5. 点四个状态按钮之一：`未核对` / `已定位` / `已核对` / `失效或撤回`。只有 `已核对` 才能用于审核通过；`失效或撤回` 会阻断其关联文章的公开访问（已发布文章会立即 404/410）。
6. 重复到本篇用到的文献全部为 `已核对`。

注意：
- 「已定位」≠「已核对」。定位只表示找到了章节，不构成事实核对。
- 网络检查命令 `manage.py check_knowledge_sources` 只做链接/DNS 可达性，**不会**把文献提升为 `已核对`；`challenge_page`、`manual_check_required` 需要人工打开原文。

## 3. 逐条核验结论与证据

1. 切到「文章」页签，状态下拉选「待医学审核」，点「打开」。
2. 向下找到「重要医学结论与原文定位」。每条结论下有 1–2 条证据，字段是：原始文献、章节／页码／表格、证据解释与适用限制、核验状态。
3. 先在下方「审核／撤稿意见」里写好本条证据的意见（**按钮在意见为空时是禁用的**），例如：`对照 SOSORT 2018 版第 4 节 Table 10，支持“支具用于仍生长且有进展风险者”，但原文未给出统一时长下限`。
4. 点该条证据下的「使用下方审核意见核对这条证据」。证据状态变为「已核对」，并记录核验人、时间与文献快照。
5. 若证据位置写的是「主题级章节（待逐句核对）」（16 篇 `TOPIC-*` 专题稿都是这样），必须自己打开原文补出具体段落／表格后再核验，否则等于没有定位。
6. 发现结论与原文不符：不要核验，直接走第 4 步的「要求修改」，并在意见里写清要改成什么。

系统会拦的情况：
- `重要结论尚未完成逐条证据核验` → 还有重要结论没有 `verified` 证据。
- `先核对文献元数据，并填写支持程度、适用范围及具体原文位置核验意见` → 文献还不是 `verified`，或意见为空。
- `仅独立医学审核人可核验待审核稿的证据` → 当前账号不是审核角色，或该稿是本人编辑。

## 4. 审核通过 / 要求修改

在同一个编辑区底部「医学审核与发布」：

- **通过**：勾选「我已逐条核对所有重要医学结论」和「我已核查文字与插图的使用权」，填好意见，点「医学审核通过」。
  - 系统会再次校验：重要结论都有已核验证据、本篇文献全部 `已核对`、证据快照与文献当前元数据一致。
  - 通过后 `review_due_date` 自动设为审核后 180 天（内容运营提醒，不是患者复诊计划）。
- **退回**：填意见后点「要求修改」。版本回到 `changes` 状态，编辑方可改稿并重新提交；审核记录保留。
- 报错 `仅可审核待审核版本，且不可审核自己的编辑稿` → 换审核人，或让编辑另建版本。

## 5. 发布与撤稿（管理员）

- 发布：状态为 `approved` 时点「发布此版本」。发布前会校验审核摘要 `content_digest` 与当前内容一致、文献快照未变；不一致会提示「审核后来源元数据改变，请创建新版本重新审核」。
- 撤稿：已发布状态下填原因，点「按所填原因撤稿」，公开端立即不可访问。
- 已发布版本不能原地修改：任何内容变更都要新建版本（「创建新版本」），重新走审核。

## 6. 批量与命令行（可选）

审核人通常用界面逐条核验即可。需要脚本化时（需 reviewer token）：

```powershell
$login = Invoke-RestMethod 'http://127.0.0.1:8000/api/v1/auth/login/' -Method Post `
  -Body (@{username='kb-reviewer';password='<密码>'} | ConvertTo-Json) -ContentType 'application/json'
$h = @{ Authorization = "Token $($login.data.token)" }

# 文献核验
Invoke-RestMethod 'http://127.0.0.1:8000/api/v1/knowledge/manage/sources/NIAMS/verify/' -Method Post `
  -Headers $h -ContentType 'application/json' -Body (@{status='verified';note='已核对原文第 2 节'} | ConvertTo-Json)

# 证据核验（evidence id 从文章详情拿）
Invoke-RestMethod 'http://127.0.0.1:8000/api/v1/knowledge/manage/evidence/123/verify/' -Method Post `
  -Headers $h -ContentType 'application/json' -Body (@{note='支持程度、限制与原文位置'} | ConvertTo-Json)
```

批量脚本必须先跑一遍预检：`GET /api/v1/knowledge/manage/articles/?status=submitted`，逐篇看 `claims[].evidence[].verification_status`。
