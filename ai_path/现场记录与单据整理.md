# 现场记录与单据整理

2026-10-17：重做当前 `miniprogram-demo/pages/card`，保留已有训练首页和记录流程。

页面按现场视频、病例单/训练方案单、识别动作对应、当前要求核对组织。录制自动保存草稿，同一轮现场录制的多个视频共享本轮资料。可先录视频，也可先上传资料或根据明确的现场指导手动建卡。资料未齐时可以先存草稿；已核对后才显示完整的学、练、查入口。

浏览器 demo 使用项目原有 Windows OCR，新增 `POST /api/recognize-document` 本机接口，不向外部服务发送单据。支持 JPG/PNG 单页图片，图片不超过 8 MB；识别失败可重试或手动校对原文。原件在本机保留，OCR 临时文件在成功和失败后均清理。

病例单展示原文摘录，供核对个人资料和注意事项。只有训练方案原文中明确写出的动作、组数、每组次数/秒/呼吸次数、个人要点和频次会形成候选。空白、范围或冲突项不填默认值；频次作为来源提示，建立计划时仍需确认。

选择候选可补入当前视频对应的动作草稿，字段可继续修改。要求核对并保存后才能加入计划。候选按文档与动作名称保留对应关系，插入或调整方案原文中的动作顺序不会串视频。异步识别不会覆盖后来手动校对的文字。

修改位置：

- `pages/card/index.wxml` / `index.wxss`：页面布局、状态与样式。
- `pages/card/index.js`：资料上传、识别、视频对应与保存交互。
- `core/documents.js`：独立资料存储、保守原文提取。
- `core/document-recognition.js`：本机 OCR 适配。
- `scripts/demo-ocr.cjs`、`scripts/serve-demo.cjs`：本机识别和预览接口。

浏览器通过 `http://127.0.0.1:4180/#/pages/card/index` 体验。没有指定动作时恢复最近未整理的现场草稿；训练首页“按指导建卡”明确建立新卡，不带入上一轮资料。源文件保存后自动刷新，后台服务变更需重启 `node scripts/serve-demo.cjs`。

已验证：`scripts/check-demo.cjs`、`scripts/check-demo-documents.cjs`、`scripts/check-card-organizer.cjs`，以及 `scripts/check-demo-ocr.cjs` 的真实 Windows OCR。浏览器验证覆盖双文档真实识别、确认门槛、原文校对、失败重试、资料持久保存与 375/390 手机布局；截图与检查记录在 `output/organizer-preview/`。微信原生摄像、播放器和真机访问本机服务仍需在开发者工具或真机验收；正式部署需使用正式鉴权接口。
