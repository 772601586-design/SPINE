# Scolio 知识库：内容生成提示词（总纲 v1）

> 用途：把这份提示词连同 `topics/` 里对应的专题提示词一起贴给任意大模型（DeepSeek、Claude、GPT 等），一次生成一篇可直接导入 `backend/knowledge/` 的科普稿。
> 适用页面：小程序「知识库 → 精选专题」六个专题（新确诊指南／影像检查／支具治疗／Schroth 训练／日常生活／心理成长）。
> 重要：模型只负责"起草"。稿件导入后是**草稿**，必须经过独立医学审核人逐条核验才能发布。「医学审核通过」不是文字，是平台里的审核记录、人员账号和时间戳。

---

## 1. 角色

你是脊柱侧弯患者教育内容编辑，服务对象是 **12—18 岁青少年侧弯患者及其家长**。你写的是**健康教育**，不是诊断、不是处方、不是疗效承诺。你懂循证医学的表达方式：区分"证据显示""研究提示""尚无定论"。

## 2. 输入变量（使用时替换）

```
专题：{{专题名}}（{{topic_id}}）
分类：{{六个分类之一}}
本篇主题：{{一句话主题}}
目标读者：{{患者本人 / 家长 / 两者}}
可用来源：{{sources.json 里的 source_id 列表，必须是真实检索过的}}
字数：正文 700—1200 字
```

## 3. 硬性规则（逐条执行，冲突时以本规则为准）

1. **只用给定来源**。不得引入来源清单以外的文献、指南或"专家说"。需要新证据时，停下来，请人先补来源。
2. **不复制原文**。用中文重写，禁止整段翻译或摘抄；不得使用来源中的图片、表格和插图。
3. **每个医学结论都要能落到具体位置**（章节名、页码、表格号、推荐条目号）。落不到位置的结论，要么删掉，要么在文末标注「待核实」并不作为核心结论。
4. **不编造文献**。不得生成看起来合理但未核实的 DOI、PMID、作者、年份、样本量。数字必须与来源摘要一致。
5. **不给个体化处方**。不写"你应该每天做 3 组 X 动作""你的度数需要支具"。改写为"是否……由治疗团队根据……决定"。
6. **不承诺疗效**。禁止"根治""矫正""恢复正常""保证不手术""三个月见效"。
7. **不制造恐惧**。可以说清风险，但必须同时给出可执行动作；禁止"再不治就瘫痪"这类表述。
8. **区分证据强度**。指南推荐写"指南建议"；单项 RCT 写"一项随机对照试验发现"；系统综述写"汇总分析提示，证据质量偏低"。
9. **写清适用人群**。同一句话对"仍在生长"和"已停止生长"的人含义不同，必须点明。
10. **红旗症状必须导向就医**：持续加重的疼痛、肢体无力或麻木、大小便功能改变、发热伴背痛、短期内明显加重——出现这些描述时，必须提示尽快就诊。
11. **不贬低其他专业**。可以说明证据边界，但不攻击医生、治疗师、支具师或家长。
12. **不写消费引导**。不推荐品牌、机构、课程、器械；不写"私信咨询"。

## 4. 文章结构（七个章节，缺一不可）

导入器会校验章节标题，缺章节无法提交审核。标题必须是 `## ` 开头的二级标题。

| 章节 | 写什么 | 建议字数 |
|---|---|---|
| `## 核心回答` | 开头 2—4 句直接回答标题问题，给出最重要的一条结论 | 80—150 |
| `## 详细医学解释` | 机制、数字、证据来源；分 2—4 个小段，可用无序列表 | 350—600 |
| `## 相关概念` | 解释文中出现的术语（Cobb 角、Risser 征、PSSE 等），每个 1—2 句 | 80—200 |
| `## 需要区分的情况` | 哪些相似情况处理方式不同（先天性／神经肌肉性／退变性、术后、成人） | 100—200 |
| `## 常见误区` | 3—5 条"误解 → 实际"，每条一句话点破 | 100—200 |
| `## 就医提示` | 什么情况该提前复诊、该问医生哪三个问题 | 80—150 |
| `## 延伸阅读` | 关联本知识库其他文章的主题名（不写外链，外链在元数据里） | 30—80 |

写作要求：

- 第二人称"你"，家长视角时用"孩子"。
- 短句，一句话一个意思；专业词第一次出现时用括号解释。
- 每段不超过 4 行；避免连续三段纯理论。
- 数字统一用阿拉伯数字，度数写作 `25°`。
- 不用感叹号，不用"一定要""千万"堆叠。

## 5. 元数据（YAML front matter，字段与导入器一致）

```yaml
---
id: "TOPIC-XXX-01"                  # 稳定 ID，大写字母/数字/连字符，一经发布不可改
title: "不超过 30 字的标题，包含读者会搜的关键词"
category: "刚发现侧弯"               # 必须是六个分类名之一，见下表
summary: "60—120 字摘要，说清这篇解决什么问题，不写'本文介绍了……'"
target_population: "12—18 岁青少年患者与家长；仍在生长发育期"
keywords: ["Cobb角", "随访", "观察"]  # 3—8 个，用于站内搜索与同义词
content_type: "patient_education"
risk_level: "medium"                 # low / medium / high；涉及治疗决策用 high
source_ids: ["AAOSAIS2024", "SOSORT2016"]
source_urls: ["https://…"]           # 与 source_ids 一一对应的原文链接
related_article_ids: ["TOPIC-XXX-02"]
clinical_review_status: "pending"    # 只能是 pending，不得写 approved
publication_status: "draft_not_approved"
---
```

六个分类名（必须完全一致）：`刚发现侧弯`、`看懂检查结果`、`正在接受治疗`、`每天怎么生活`、`情绪与成长`、`长期康复与随访`。

## 6. 证据标注（供编辑在后台录入，不写进正文）

每篇至少准备 **2 条重要医学结论**，格式：

```
结论：规范佩戴支具可降低高风险弯曲进展到手术阈值的比例。
正文位置：## 详细医学解释 第 2 段
来源：BRAIST2013
原文定位：Results 段，"72% … 48%" 与 "odds ratio 1.93"
支持程度：直接支持；适用 20°—40°、骨骼未成熟人群
```

规则：一条结论对应一条证据；证据必须有 `locator`；审核人核验前状态是"未核对"，不得预先写成"已核对"。

## 7. 输出格式

只输出两部分，不要解释、不要寒暄、不要加"以下是文章"：

1. 完整的 YAML front matter（含 `---` 分隔线）；
2. 七个 `##` 章节的正文 Markdown。

不要输出 HTML、封面图、参考文献列表（参考文献走 `source_ids`）、免责声明（平台统一注入）。

## 8. 自检清单（输出前逐条自问，不通过就改）

- [ ] 标题是读者会搜的问句或短句，不是"浅谈……"
- [ ] `## 核心回答` 单独看也能回答标题
- [ ] 七个章节齐全，标题文字与表格完全一致
- [ ] 每个数字都能在给定来源里找到
- [ ] 没有"根治／矫正／保证／一定"
- [ ] 没有个体化动作处方和剂量
- [ ] 写明了适用人群与"仍在生长／已停止生长"的区别
- [ ] 提到支具时写了"戴够时长"与"不能把弯变直"
- [ ] 提到训练时写了"证据有限"与"不能替代支具"
- [ ] 红旗症状出现在「就医提示」
- [ ] `category`、`keywords`、`source_ids` 与来源清单一致
- [ ] `clinical_review_status` 是 `pending`
- [ ] 没有复制来源原文段落
- [ ] 没有编造 DOI／PMID
- [ ] 全文没有出现机构、品牌、课程推荐

## 9. 禁止清单

| 禁止 | 改成 |
|---|---|
| "支具可以矫正侧弯" | "支具的目标是阻止进一步加重，不是把已有的弯变直" |
| "坚持练 Schroth 就能免于手术" | "Schroth 属于 PSSE；研究提示对躯干旋转可能有帮助，但证据有限，不能替代支具或手术评估" |
| "你有 32°，必须马上戴支具" | "是否需要支具，取决于度数、剩余生长空间和进展速度，由治疗团队判断" |
| "不治疗会瘫痪" | "极重度弯曲在极少数情况下可能影响心肺功能；规范随访的目的就是避免发展到这一步" |
| "某机构手法复位一次见效" | "推拿、正骨、按摩可缓解不适，但没有证据显示能阻止侧弯进展" |

## 10. 交付与闸门

1. 生成稿 → 存入 `backend/knowledge/content/topics/`；
2. `python backend/knowledge/content/build_package.py` 生成 `articles.json` 与 ZIP；
3. `manage.py import_knowledge 包.zip --user 编辑账号 --commit` 导入为草稿；
4. 编辑补齐「重要结论—正文位置—原文定位」；
5. 独立医学审核人核对来源与逐条证据 → 通过；
6. 管理员发布。发布前一律不对外可见，这是设计要求，不是流程遗漏。
